# ЛР-6. Робота зі складними формами та валідація

Стартовий проєкт лабораторної роботи № 6 курсу «Розробка вебзастосунків на
React»: форма бронювання столика з ЛР-5. Інструкція:
https://denysmatsevych.github.io/web-development-2026/react/labs/lab-6/

Форма працює так, як ви залишили її наприкінці ЛР-5, і перевіряє лише
обов'язкові поля (`required`). Ви опишете правила форми схемою Zod, передасте
значення полів React Hook Form, покажете повідомлення про помилки під полями
й надсилатимете бронювання на сервер через Action React 19.

## Що вже є

- форма з ЛР-5 (`src/components/BookingForm.jsx`) і контрольований
  `GuestsStepper`;
- нове поле «Телефон» і порожні абзаци для повідомлень про помилки під полями
  «Ім'я», «Телефон», «Дата» й «Час»;
- `src/api.js`: імітований сервер кав'ярні, який відповідає за секунду;
- `src/bookingSchema.js`: функції `today()` і `nowTime()` і порожня схема,
  яку ви заповните;
- стилі для повідомлень про помилки, стану очікування й форми підписки в
  `src/index.css`;
- бібліотеки `react-hook-form`, `zod` і `@hookform/resolvers` у
  `package.json`: `npm install` у корені встановить їх разом з іншими.

## Команди

`npm install` виконуйте в корені репозиторію `react-labs`, решту — у теці
`lab-6/`:

- `npm run dev`: dev-сервер на http://localhost:5173
- `npm run lint`: ESLint
- `npm run format:check`: перевірка форматування Prettier
- `npm run build`: production-збірка в `dist/`

## Порівняння React Hook Form + Zod (`lab-6`) та Formik + Yup (`lab-6-alt`)

| Критерій | `lab-6` (React Hook Form + Zod) | `lab-6-alt` (Formik + Yup) |
| --- | --- | --- |
| **Розмір JS-бандлу (`vite build`)** | **353.70 kB** (gzip: **109.36 kB**), 120 модулів | **359.24 kB** (gzip: **111.51 kB**), 247 модулів |
| **Модель стану та рендери** | Неконтрольовані поля через `ref` (`register`) — введення тексту не перемальовує форму | Контрольовані значення у стані React — кожне введення викликає рендер форми |
| **Кастомні компоненти** | Потрібна обгортка `<Controller>` для `GuestsStepper` | Пряма передача `formik.values.guests` і `formik.setFieldValue` без обгорток |
| **Валідація схеми** | `safeParse()` повертає `{ success, data, error }` без винятків; залежні поля через `.refine()` | `validate()` кидає виняток (`try / catch`), перед відправкою потрібен `cast()`; доступ до сусіднього поля через `this.parent` |
| **Фокус при помилках** | Автоматично переводить фокус у перше поле з помилкою під час сабміту | Потрібен ручний пошук першого невалідного інпуту через `ref` і виклик `.focus()` |

### Висновки

1. **Продуктивність і розмір:** React Hook Form + Zod формує компактніший бандл (`353.70 kB` проти `359.24 kB`, навіть попри те що у `lab-6-alt` також залишився `zod` для форми підписки) і не перерендерює всю форму під час набору тексту.
2. **Керування формою та фокусом:** у React Hook Form валідація при втраті фокуса (`mode: 'onTouched'`) і переведення курсора в перше поле з помилкою працюють «з коробки». У Formik довелося вручну обробляти `validateForm()`, проставляти `setTouched` для всіх полів і шукати перший інпут через `querySelector`.
3. **Інтеграція кастомних полів:** у Formik підключення степера гостей виглядає трохи лаконічніше через `setFieldValue`, тоді як у React Hook Form для цього потрібен компонент `Controller`.
